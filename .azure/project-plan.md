# Agata Nowak Portfolio

## Approval and assumptions

Proceeding on the basis of the user's request to build a portfolio inspired by the linked 3D portfolio. The user is unavailable to review implementation details, so this plan uses conservative defaults. No backend, database, deployment, or public street address/date of birth is in scope.

## Goal

Create an original, responsive, single-page portfolio for Agata Anna Nowak, a Process Engineer, using the CV provided by the user as the source of truth. Use the linked site as visual inspiration for a polished 3D hero and section-based portfolio; do not copy its source code or assets.

## Audience and language

- Recruiters and operations, process-improvement, and supply-chain teams.
- English.

## Content

- Hero: Agata Anna Nowak, Process Engineer, and a concise introduction based on the CV.
- About: planning, logistics, data-driven improvement, collaboration, and communication.
- Experience: current Process Engineer role and relevant planning, MRP, and reverse supply chain roles from the CV.
- Education: management/production engineering and commodity science studies.
- Skills: SAP ERP, Power BI, MS Office, SolidWorks, AutoCAD, Six Sigma Yellow Belt, process-flow analysis, and listed transferable skills.
- Languages: English (C1), German (A1), Italian (A1).
- Contact: email only; do not publish the CV's phone number, street address, or date of birth.
- Do not invent software projects, client testimonials, metrics, or achievements not supported by the CV.

## Experience and visual direction

- React single-page portfolio with a 3D-inspired hero and tasteful motion.
- Distinct sections for About, Experience, Education, Skills, and Contact.
- Professional, modern visual design that reflects process engineering and supply-chain work rather than presenting the user as a software developer.
- Reuse the user's CV portrait only if it can be extracted cleanly; otherwise use a designed visual rather than a fabricated portrait.
- Responsive layout, keyboard-accessible navigation, reduced-motion support, and clear contrast.

## Technical scope

- Static frontend; no API, authentication, database, or cloud services.
- Use the existing repository state and select the simplest maintainable React setup suitable for the project.
- Validate with the available build and focused checks.

## Out of scope

- Deployment, hosting, analytics, contact-form backend, and publishing personal phone/address/date-of-birth details.
- Copying code, branding, or assets from the referenced repository.
